# pitfalls · 踩坑清单（动手前先扫一遍）

## 会让结果**静默错误**的（最危险，不报错）

| 现象 | 原因 | 处理 |
|---|---|---|
| 改了策略但回测结果一模一样 | 引擎复用了结果缓存 | Freqtrade 必带 `--cache none`；自研引擎回测入口禁用一切缓存，或把代码 hash 进缓存 key |
| 搜参怎么调结果都一样 | 因子在 `populate_indicators` 里算，而只优化 buy space 时该函数不重跑 → 参数静默失效 | 把因子挪到 entry/exit 阶段算，或用**参数签名**做面板缓存的 key（参数一变必重算） |
| 策略的 timeframe 设置不生效 | config 里的 `timeframe` 字段覆盖了策略里的 | 删掉 config 的 `timeframe` 字段 |
| 夏普比别人高一大截 | 用了「按每笔交易」的夏普，并发持仓越多越虚高 | 只认 `Sharpe (daily wallet balance)` / 日频资金曲线口径 |
| 横截面因子映射后全是 NaN | 用 `.values` 剥掉了时区，与 tz-aware 的 date 对不上 | 保留 tz-aware index，按日期 map |
| 不同时间重下数据对不上 | 复权/退市/接口已变，原始响应没存 | 原始层只追加，保存 URL/查询、时间、SHA256 和清洗代码版本 |
| 回测赚钱、实盘对不上 | 用当根 K 线收盘价做当根决策 | 写信息→决策→成交→PnL 时序；PnL 起点不得早于成交 |
| `shift(1)` 通过但收益仍虚高 | 跨市场信号在美国收盘才产生，却记了当地前收→今收 | 至少拆 overnight 与 open→close；若交易期货，必须用当时真实期货报价 |
| OOS 业绩 2000 天、MC 却有 7000 条 | OOS returns 与 FULL trades/panel 被拼进同一报告 | 候选 MC 统一用 OOS 日收益；严格报告校验所有输入窗口 |
| 报告写“全过”但某层是 error | 验收逻辑只在字段存在时判断，缺失反而通过 | 候选门禁 fail-closed；缺失、error、样本不足都不得 PASS |

## 会让**结论作废**的方法论坑

| 坑 | 说明 |
|---|---|
| 看过 OOS 后把新规则仍称原假设 | 迭代本身允许，但搜索次数被抹掉 | 新规则建 lineage/新版本，旧 OOS 进入开发历史，全部尝试计入账本 |
| 搜完参数才改目标函数且不记账 | 等于隐藏一次模型选择 | 可以提出新目标，但必须新建 trial/版本并用后续 walk-forward 或实时数据验证 |
| 按表现挑标的 | 幸存者偏差。宇宙开发前定死；即便定死了，"这 20 个是今天回头挑的"本身也是偏差，要在局限里写明 |
| 只报最好一轮 | DSR 算不了，等于放弃回答"是不是搜出来的" |
| 直接取 argmax | 先算 train/valid 相关性 r；r 低 = 验证排名是噪音，argmax 是"N 次抽样里最大的噪声" |
| 用框架自带的 lookahead 检查给横截面策略背书 | 对横截面**会误报**（边界 K 线排名天然变化）；以全量 vs 截断对照为准 |
| 只看总收益不看多空分侧 | 熊市里空头没赚钱，是比总收益为负严重得多的信号 |
| 用复利总收益去和日收益加总口径的 α 归因对齐 | 两套口径不能混，报告里各自标明 |
| 把低 beta/小回撤写成 alpha | 风险角色与 alpha 角色混淆；用同样 beta 的基准后通常没有增量 |
| 只看统计显著，不看经济下界 | 几个 bp 的显著收益可能连成本误差都覆盖不了；报告压力成本和置信下界 |
| 每张卡单独显著就当活动成功 | 从几十张卡里挑赢家仍有活动级多重检验；最终候选做 FDR/Reality Check 或前瞻验证 |

## 环境类

| 现象 | 处理 |
|---|---|
| Git Bash 挂载路径被 MSYS 改写成 `D:/...` | `export MSYS_NO_PATHCONV=1` |
| PowerShell 5.1 不认 `&&` | 分两行写 |
| `--export-filename` 不生效 | 新版 Freqtrade 统一落 `backtest_results/backtest-result-<ts>.zip`，直接读 zip |
| 容器里跑分析脚本缺 numpy/matplotlib | 分析脚本在**宿主机**跑（只需 numpy+pandas）；只有 import 框架的脚本才进容器，且要 `--entrypoint python` |
| 数据源在墙内/生产机上不稳定 | 把行情烤成本地 seed 文件随代码走，别指望部署环境能实时拉到 |
