# 可交易策略研究协议

目标不是制造一条通过统计考试的曲线，而是提高单位研究时间找到下面这种东西的概率：

> **有可解释的收益来源，信息在下单前可得，收益能以真实价格捕获，扣完完整成本仍有余量，换时期和换起点仍成立，并能改善现有组合。**

把策略价值拆成：

`组合价值 = 可持续预测力 × 可捕获比例 − 交易/融资/冲击成本 − 尾部与容量代价`

任何检验都要回答其中一个问题；不回答问题的流程不做。TEST 物理隔离是可选的高置信度增强，不是研究有效性的中心。核心证据来自滚动样本外、完整搜索记账、成交时序和独立复现。

## 七条硬约束

1. **先声明策略角色。** alpha、分散器、尾部对冲、执行改进的基准和成功条件不同，不能都用“alpha t≥2”一刀切。
2. **信息时间不晚于决策，决策不晚于成交，PnL 不早于成交。** 必须写 `information_time → decision_time → execution_time → pnl_interval`。只写 `shift(1)` 不算成交证明。
3. **宇宙与字段必须 PIT。** 上市、退市、停牌、公告、成分、复权、合约换月都按当时可知口径；做不到就标记代理研究，不得称可交易回测。
4. **成本是输入，不是美化曲线的旋钮。** 费用、价差、滑点、冲击、借券、资金费、融资和不可成交都按市场年鉴锁死，并做至少一档压力成本。
5. **所有尝试进入同一搜索账本。** 参数、过滤器、资产池、区间、目标函数和失败变体都算一次尝试；只记录赢家等于隐瞒过拟合。
6. **绩效统一用日频资金曲线。** 不用逐笔夏普；策略、基准、MC、置换必须使用同一评价窗口。
7. **晋级门禁 fail-closed。** 必要输入缺失、统计报错、窗口错位或数据来源不完整，都不能 PASS；探索阶段可继续，但只能标记为诊断。

## 先选角色，再选验收标准

| 角色 | 真正的问题 | 最低可用证据 |
|---|---|---|
| alpha | 选择/择时是否创造净超额 | 风险匹配基准后净 alpha 为正、置信下界过线、匹配置换过线 |
| 分散器 | 是否改善已有组合 | 固定事前权重后，滚动 OOS 的组合 Sharpe/Calmar 或回撤改善；不能只报自身收益 |
| 尾部对冲 | 危机保护是否值得长期保费 | 预定义压力窗口损失显著下降，正常期成本在预算内，极端成交可行 |
| 执行改进 | 是否比原执行少付成本 | 同订单流/同风险下 implementation shortfall 稳定下降 |

`qbt.py report` 当前直接覆盖 alpha 角色。其他角色必须提供角色专用对照报告，不能拿低 beta 冒充 alpha。

## 三层研究漏斗

### A. 快速证伪：先判断值不值得精做

在最小数据和最小引擎上依次问：

1. 机理：谁在持续付钱，为什么不会被立刻套利掉？
2. 毛边际：信号的毛收益上限是否至少是保守总成本的 2~3 倍？
3. 可捕获：信号公布后还有多少收益，而不是信号公布前已经跳完？
4. 增量：同池等权、静态暴露、简单动量/反转能否解释结果？
5. 稳定：方向是否跨年份、市场状态、相邻参数保持？

任何一项明显失败就尽早停。快速 FAIL 是节省预算，不必为已死想法补齐全套漂亮报告。

第 2 问不许停留在定性判断，**写任何回测代码之前**先把它算成一个数：

```bash
python scripts/qbt.py screen --gross-annual 0.05 --turnover 120 --cost-bps 5 --out screen.json
```

毛/成本 ≥ 3 且压力成本下仍 ≥ 1 → `GO`；2~3 → `THIN`（成本假设必须锁死并做压力档）；< 2 → `STOP`，
不要再写实现。这一闸的成本是一条命令，而它能提前判掉的是整套 B/C 层工作量。

### B. 可交易验证：把信号变成真实订单

通过快速筛选后才做完整实现：

- 按时间做 expanding/rolling walk-forward；有重叠标签时使用 purge/embargo。
- 参数只从先验或小网格来，选择参数平台而不是尖锐 argmax。
- 保存每一轮 train/valid/OOS 得分、换手、成本和失败原因。
- 输出逐日目标仓位、实际仓位、成交、成本和日收益，使每一分钱都能从仓位与价格重建。
- 创建 `execution_manifest.json` 和 `data_manifest.json`；格式见 `references/protocol.md`。
- 用 `causality_check.py` 检查前缀稳定；再人工/程序检查成交时序。前缀稳定不能替代成交验证。

### C. 候选晋级：统计、组合和实时三关

先跑严格报告：

```bash
python scripts/qbt.py report \
  --returns oos_returns.csv --bench oos_benchmark.csv \
  --trials trials.json --panel oos_universe_returns.csv \
  --execution-manifest execution_manifest.json \
  --data-manifest data_manifest.json \
  --market cn_stock --out verified/Hxxxx/verdict.json
```

时序、事件等不适合随机选股的策略，用匹配在市比例、持仓段长度、星期几、换手或事件频率的自定义置换，输出 JSON 后传 `--permutation-result`。

只有一个真正事前锁死的规格时，显式传 `--single-spec`，工具使用 PSR；只要试过别的参数、市场、过滤器或规则，就必须保存全部 trials 并使用 DSR。

严格报告通过后仍只叫**候选**，还要完成：

1. **组合增量**：用事前固定的小权重加入现有基线组合，检查滚动 OOS 的收益、回撤、相关性和容量。
2. **实时 paper trading**：记录真实信号时间、可见报价、预期成交、实际可成交量和偏差；时间长度至少覆盖足够事件/交易次数，而不是机械规定几个月。
3. **独立复现**：任何准备上资金的候选，由另一个实现从原始数据重建。物理隔离 TEST 可用于最终高置信度确认，但不是替代前两项。

## 统计判读

- alpha 用 Newey-West/HAC 标准误；普通 OLS t 不得标成 NW t。
- 搜索过多个规格：DSR ≥ 0.90 才可继续，≥0.95 更可信。
- 单一锁死规格：PSR ≥ 0.90；同时明确它没有校正整个研究活动的多假设搜索。
- 路径重采样统一使用 OOS 日收益；`prob(profit) ≥ 95%` 或 P5 终值为正，才算路径稳健。逐笔 MC 只能作成交诊断。
- 置换必须匹配策略结构和成本，真实结果至少位于随机分布 95% 分位。
- 关注经济下界：净 alpha 的量级必须覆盖模型误差和加倍成本；统计显著但只有几 bp 的策略仍可能无用。
- 做逐年剔除、滚动窗口、起点和相邻参数检查；看稳定平台，不看单一最优点。
- 同一活动批量探索很多题目时，在最终候选层做 FDR/Reality Check 或保留活动级前瞻样本。单卡 DSR 不能消除“从几十张卡里挑最好”的偏差。

## 裁决含义

- **FAIL**：机理、数据、成交、成本或增量已经被证伪。保留死因和可复用组件。
- **PARK**：信息可能存在，但证据、数据、容量、近期有效性或组合价值不足；必须写重启条件。
- **PASS**：严格候选门禁通过，可以进入组合评估和 paper trading；**不等于直接实盘**。
- **LIVE**：不由回测工具自动授予，只能在实时执行、容量和风控通过后由人决定。

## 工具

- `scripts/causality_check.py`：检查全量与截断数据上的决策是否一致，只回答“有没有依赖未来数据”。
- `scripts/qbt.py screen`：A 层成本闸，把「毛边际 / 成本」算成一个数并给出 GO/THIN/STOP。
- `scripts/qbt.py`：统一日频绩效、HAC alpha、DSR/PSR、日收益分块自助、随机组合和严格候选门禁。`--exploratory` 只生成诊断，不能用于 PASS。

不要复制脚本到业务目录后各改一版。扩展通用检验时修改 skill 脚本并加测试；策略特有的零假设留在课题目录，通过标准 JSON 接入。
