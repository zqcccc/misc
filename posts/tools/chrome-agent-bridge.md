# 市面上的 AI 浏览器很多，为什么我还是把日常 Chrome 借给它

日常排查云平台故障、翻看监控告警日志、核对系统账目，或者搜集那些没有公开接口的资料，浏览器往往是唯一的入口。

把提示词写得再繁复，如果 AI 只能停留在对话框里回复文字，真正需要操作的业务它依然碰不到。让 AI 能接管浏览器，自动化流程才算真正开始干活。

只是目前市面上的现成工具，用起来几乎都有让人难以接受的摩擦。

## 定制浏览器很炫，日常根本用不起来

第一种做法是使用独立的 AI 定制浏览器。这类工具自带沙箱和自动化组件，功能看似完备，却忽略了一个最基础的现实：没有人会把它们当成主力工具。

工作和生活中的全套状态，全都保存在平时用的 Chrome 里面。公司的 SSO 单点登录、阿里云或 AWS 的控制台、GitHub、工作邮箱、日常沟通平台，几十个账号的登录凭据都在这里。

换一个全新安装的定制浏览器，每次让 AI 去查点东西，都得把这一串账号重新登录一遍。遇到手机扫码或者双因素认证，折腾起来格外费劲。原本是为了让 AI 帮忙省下几分钟，结果在登录认证上倒耗费了半小时。

## 弹窗打扰与风控拦截的双重麻烦

既然定制环境不方便，自然会考虑直接连接本地已有的 Chrome。

常见的方案普遍存在两类使用阻碍。

一类是调用 Chrome DevTools Protocol，也就是 CDP 远程调试。很多网页读取插件走的都是这条路线。只要一唤起调试，Chrome 窗口顶部就会始终显示一条刺眼的黄色横条，提示“Chrome 正在受到自动测试软件的控制”，时不时还会弹出权限确认对话框。在正敲代码或者阅读资料的时候，焦点冷不丁被弹窗夺走，打断输入节奏。

另一类方案是直接引入 Playwright 或 Puppeteer。这些自动化测试框架设计之初是为了在持续集成流水线上跑断言，浏览器内部默认带着 `navigator.webdriver` 标记，网络层也是典型的机器指纹。遇到具备风控机制的业务管理后台或内容社区，立刻触发拼图滑块验证，严重的直接返回 403 阻断访问。

## 借用日常 Chrome 的中转方案

保留已有登录凭据并避开风控检测，最自然的思路就是直接把平时在用的 Chrome 借给 AI。

OpenAI 的 ChatGPT for Chrome 和 Anthropic 的 Claude in Chrome 官方插件给出了相似的参考：在 Chrome 内部安装原生扩展，通过操作系统的 Native Messaging 管道与本地进程进行数据交互。

我写的工具叫 chrome-agent-bridge，正是采用这套结构。

本地运行一个极其轻量的中转进程，Chrome 里安装专用的 MV3 扩展。AI 客户端将操作指令发送给本地服务，服务通过系统级原生消息管道转发给扩展，扩展在网页内部执行 DOM 读取、模拟点击、滚动页面与截取长图。

这种结构避开了前面提到的所有缺陷。平时使用的 Chrome 里已有各种登录状态，不需要迁移凭据。它没有开启 CDP 调试端口，窗口顶部不会出现黄色的自动测试警告横条，全程保持静默。它直接复用真实的客户端环境与 TLS 特征，在风控系统看来属于正常的网页访问，不会频繁触发无限循环的验证码。

## 操作看得见、随时可中断

把主力浏览器交出去，最核心的考量是避免误操作和数据泄露。针对安全边界，工具设置了四层控制机制。

第一，操作过程完全透明。AI 接管某个标签页后，标题栏会显示醒目的红点提示“● Agent 接管中”，扩展图标亮起蓝色标记。在页面内部，AI 每次点击都会浮出一个半透明光标和一圈扩散波纹，点击了哪个按钮、正在滚动哪里，轨迹一目了然。

第二，控制权随时可以收回。页面右上角常驻红色的“停止 Agent”按钮。发现动作不对劲，鼠标点击即可立刻切断控制。如果 AI 在执行过程中停下来思考，超过 12 秒没有发出后续指令，系统会自动解除接管状态并恢复原标题。

第三，多任务调度互不干扰。工具支持几个本地 Agent 同时接入。操作不同标签页时完全并行；如果多个请求命中同一个标签页，排队锁机制会保证指令依次执行。哪怕某个 Agent 意外崩溃未能释放资源，120 秒超时机制也会自动解除锁定，避免标签页持续停滞。

第四，敏感信息拦截脱敏。读取页面数据时，内置了字段脱敏机制。密码输入框以及带有信用卡号、三位安全码、短信验证码等属性的字段，内容统一替换为 `[value redacted]` 后再传递给 AI，保证真实密码和卡号不离开浏览器。

## 适用范围与调用方式

这套工具目前主要用于几类日常事务，包括登录云控制台汇总各个实例的监控图表和告警日志、深入需要登录态的专业技术社区展开多层嵌套的评论回复提取结构化记录，以及在业务后台自动执行重复性的表单填写。

它的能力边界同样十分清晰。

当前仅适配了 macOS 平台配合 Google Chrome 的使用环境。

它绝对不会代替用户执行登录。遇到必须手动扫码、输入密码或接听语音验证码的环节，AI 会立即暂停动作并在终端提醒人工接管。完成认证、页面恢复正常状态之后，任务才会继续向下执行。

工具提供简洁的命令行接口与本地 RPC 协议，方便直接集成到各类自动化工作流。

```bash
node agent/cli.mjs tabs
node agent/cli.mjs open https://example.com
node agent/cli.mjs click "button[type=submit]"
```
