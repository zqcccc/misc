# 量化策略探索 · 长跑模式（单 agent 连续多轮自驱）

> **启动语**：`读 quant_research/PROMPT_LONGRUN.md 并严格照它执行。我的 agent 名：<name>`

这份文件**不替代** `PROMPT.md`。每一轮研究的做法、铁律、汇报格式全部照 `PROMPT.md` 执行，
这里只规定**轮与轮之间**的事：怎么自己挑下一个课题、什么不许动、什么时候必须停。

---

## 你这次和平常有什么不同

平常是"给你 N 个假设的预算，做完收工"。这次没有预算上限，你要**连续跑很多轮，自己决定做什么、
自己决定什么时候停**。没有人在旁边看着，所以三件事你要自己扛：

1. **不许为了有产出而放水。** 长跑最典型的失败模式是：跑了十几轮全是 FAIL，开始觉得
   "门槛是不是太严了"，然后动手改判读线、改成本假设、改基准，让某个课题勉强过关。
   **这会让之前 30 张卡的结论全部作废**（它们是按现在这套门禁判的）。见下面「不许动的东西」。
2. **状态在台账里，不在你的上下文里。** 你的上下文会被压缩甚至重开，台账不会。
   任何"我记得刚才……"都不可靠，任何结论都必须落进假设卡或 `KNOWLEDGE.md`。
3. **该停就停。** 无限跑不是目标，见下面「必须停下来的情况」。

## 主循环

```
开工一次：  ./qr start --agent <你的名字>     # 退出码非 0 就不要开始，按它列出的问题处理
            #                                   退出码 0 但点名了「被挡的市场」，就避开那些格子
            export QR_AGENT=<你的名字>        # 人读的标签
            export QR_RUN=<start 打印的 token> # 这一次运行的身份 —— 照抄它打印的那一行

loop:
  ① 盘点   ./qr leads / ./qr coverage / ./qr scorecard / cat KNOWLEDGE.md
  ② 选题   按下面的优先级挑 1 个课题（不是 N 个，长跑模式一次只推进一个）
  ③ 研究   完全照 PROMPT.md 阶段 1~3 做（含 A 层成本闸）
  ④ 收口   ./qr verdict ... --cause ... "<人话结论>"，填满卡片 §7 §8 §9
  ⑤ 自检   见下面「每轮自检」
  ⑥ 汇报   四段格式写一段（≤20 行），然后**不等人，直接回到 ①**
```

**一轮 = 一张卡从占坑到裁决。** 不要同时开好几张，也不要做到一半跳去做别的。

### 选题优先级（从上往下，上面的有货就不要往下走）

1. **`./qr leads` 里未接手的线索** —— 前人已经花过成本、确认机理为真、只差一个条件就能重开的。
   接手用 `--parent <原ID>`。**这一档的期望值明显高于开全新方向**，因为机理验证这一步已经付过费了。
2. **能解释已有结论的深挖** —— 台账里有没有两张卡的结论互相矛盾、或者某个死因反复出现却没人问
   "为什么这个市场总是这样"。H0028 就是这么来的：它挖出 A 股隔夜/日内的制度指纹，
   顺带解释了 H0001「A股动量为负」是怎么回事。**这种卡的价值高于又一张孤立的 FAIL。**
3. **`./qr coverage` 的空白格** —— 市场 × 机理族矩阵里还没人碰过的格子。
4. **全新方向** —— 走 `ai-quant-sources` 检索。**重点找负面证据**，只找到吹的没找到骂的
   等于检索没做完。

每 5 轮里至少有 1 轮是**校准位**：故意挑一个打分卡上排名中等的候选（不是最高分的），
跑到能下裁决为止就行。理由见 `PROMPT.md` 阶段 1.3——只做最高分的，打分卡永远验不出准不准。
占坑时把分数带上：`--score 9/14`。

## 不许动的东西

以下文件**你这一趟不许改**。发现它们有问题，开一条阻塞，不要自己动手：

- `.agents/skills/quant-backtest-protocol/`（协议本体：SKILL.md、qbt.py、causality_check.py、references）
- `quant_research/PROMPT.md`、`quant_research/PROMPT_LONGRUN.md`、`quant_research/qr`、`quant_research/templates/`
- 别人已经裁决的假设卡的 §7 §8（可以追加探索日志，不许改数字和裁决）

**判据是「你这一趟的增量」，不是「工作区干不干净」。** 开工时 `qr start` 会把这几组文件
的内容指纹存进 `runs/<你的名字>.env`；收工时 `qr selfcheck` 拿当前状态和那份基线比。
开工前就存在的未提交改动是维护者的事，不是你的违规，不会挡你。你改了才算。

**协议不是不能修，是不能由你在研究途中偷偷修。** 修裁判的正确流程是：你开一条 HALT 阻塞
→ 人授权后单独做维护 → `qr protocol register v<N> --impact ...` 登记新版本 → `qr rejudge`
算出哪些历史裁决需要重判。历史卡保留它们当初盖的指纹，不追溯改写，也不会"全部作废"。

同样不许做的：放宽 `--cause` 词表、放宽行话检查、调低成本假设、事后改口径/基准/区间/评价窗口、
把 `--exploratory` 的诊断报告当成 PASS 依据。

## 每轮自检（做完裁决就跑，不许跳过）

```bash
cd quant_research
./qr selfcheck --agent <你的名字>
```

一条命令一个退出码，里面已经包含：受保护文件的本轮增量、`qr audit`、未关闭的阻塞。
**退出码非 0 就立刻停下来汇报**，不要"先继续做完这轮再说"。

### 每 5 轮做一次

```bash
./qr scorecard      # 打分卡到底准不准
./qr coverage       # 地图变化
./qr leads          # 这几轮有没有产生新线索
```

然后问自己三个问题，把答案写进汇报：

- 最近 5 轮的死因是不是高度集中在同一个？（是的话说明选题器有系统性偏差，该换方向）
- 有没有哪一轮是"为了有产出而做的"？（诚实回答，有就说）
- 打分卡的高分档和中分档，结局有没有区别？（没区别说明打分卡在做无用功，写进汇报）

## 停下来的情况（分三档，不是一律全停）

**两件正交的事，分开想清楚：**

1. **有多严重** —— 会不会让别人正在做的研究得出错误结论？会 → `HALT`；
   只是让你自己这一轮做不下去 → `ASK`；两者都不是 → `WARN`。
2. **挡谁**（`--blocks`，`HALT` 必填）—— 一个 A 股数据问题不该挡住加密货币的研究：

   | 作用域 | 挡什么 | 用在 |
   |---|---|---|
   | `all` | 所有人开不了工 | 协议本身出问题、门禁能被绕过 |
   | `market:<名字>` | 只挡该市场的选题 | 某个市场的数据或口径有问题 |
   | `data:<名字>` | 只挡依赖该数据源的课题 | 数据源级别的问题（无法自动判定，靠你自觉） |
   | `card:<Hxxxx>` | 只挡这一张卡 | 出了 PASS 候选等人复核这类 |

   **默认不要写 `all`。** 2026-09-05 的教训：B0005（A 股复权口径）和 B0003
   （某张卡出了 PASS 候选待复核）两条都开成了全局 HALT，把整支编队挡了一整天，
   而它们跟加密货币、美股、外汇、利率、商品的研究毫无关系。

所有阻塞都走同一个出口，**不要只写在汇报的散文里**——下一个 agent 读不到状态，
只能重新推导一遍"这条还算不算数"：

```bash
./qr blocker open "<一句话说清卡在哪>" --severity <HALT|ASK|WARN> --evidence <可复现的路径>
```

### HALT —— 开一条阻塞，停止**受影响范围内**的循环，交给人

注意「停止循环」的范围由 `--blocks` 决定。只有 `--blocks all` 才是所有人停；
写了 `market:` / `card:` 的，你换个不受影响的方向继续跑。

1. **出现一个 PASS 候选。** PASS 意味着要往真钱的方向走，必须人来看。
   停下来，把严格报告、成交时序、数据清单、组合增量的证据一次性摆出来。
2. **`qr selfcheck` 退出码非 0**（台账有错、或你这一趟改动了受保护文件）。
   这一条天然是 `--blocks all`：台账坏了谁都别跑。
3. **你发现协议本身有缺陷。** 比如某个统计口径算错了、某个门禁能被绕过。
   这种发现比多跑十轮有价值得多。开 HALT 阻塞、附上最小复现，**不要自己改**。

### ASK —— 开一条阻塞，换个方向继续跑，不要空转等人

4. **需要花钱、需要注册账号、需要付费数据源。** 在卡里记「需付费，未取到」，换方向；
   连续三个候选都卡在这，开一条 ASK 阻塞说明这个方向整体需要预算。
5. **连续 8 轮全是 FAIL 且死因相同。** 这不是运气，是选题方式坏了。开 ASK 阻塞写清
   死因分布，然后**换一档选题优先级继续跑**，不要停在那里等人。
6. **`qr leads` 空了、`qr coverage` 没有空白格、且你想不出第 2 档的深挖题目。**
   开 ASK 阻塞，说明这一阶段的探索空间已经耗尽，该由人来决定下一步投什么。

### WARN —— 记一条，继续跑

7. 知道有个毛病但够不着当前结论的（工具输出有噪音、某个边界条件不优雅、
   文档和实现对不上但不影响判读）。记下来，别中断研究。

**一个 agent 卡住不该让整支编队停摆**，所以 `ASK` 和 `WARN` 都不挡别人的 `qr start`。

## 和别人同时跑

台账是**单例**（`./qr home` 看它在哪），所有 worktree、所有 agent 共用一份。
所以你可以在自己的 worktree 里跑，互不干扰代码，但共享同一本账：

```bash
git worktree add ../misc-<你的名字> -b research-<你的名字>
cd ../misc-<你的名字> && quant_research/qr home    # 应该指回主检出的 quant_research
```

规则：

- **名字是标签，`QR_RUN` 才是身份。** 同名并发是正常的（两个 `claude` 同时跑没问题），
  所以归属和开工基线都按 `qr start` 铸出来的 **run token** 走，不按名字走。
  照抄 `qr start` 打印的那两行 export 即可。
  忘了带 `QR_RUN` 时：名下只有一个运行 → 自动认出来，不打扰你；有多个 → **直接报错并列出可选的
  token**，不猜。歧义必须是错误，不能是默认 —— 实测过：两个同名 agent 并发时，
  归属保护会完全失效（互相能覆盖成本闸与裁决），更糟的是 A 号改了协议后 B 号一开工就覆盖了
  基线文件，A 号的收工自检会报「协议未变、自检通过」，**审计本身被绕过**。
- **只裁决自己占的坑。** 别人的坑你只能 `qr note` 留痕，`qr verdict` / `qr release` 会被拒。
- **接管僵尸占坑必须 compare-and-swap**：`./qr takeover <ID> --expect <原坑主的 run token> --agent <你>`。
  `--expect` 对不上说明有人先接了，重跑 `./qr stale` 再决定；没到僵尸线（默认 6h）不给接。
- **写台账的命令是串行的**（`qr` 内部有锁），并发调用会排队而不是互相覆盖，不用自己加 sleep。
- **`REGISTRY.md` 和 `KNOWLEDGE.md` 是派生视图**，由 `qr index` / `qr knowledge` 从假设卡整体重建。
  永远不要手改这两个文件——你的手改会在下一次别人裁决时被覆盖掉。

## 上下文快满的时候

不要试图在上下文里保住全局状态——它本来就不该在那里。做法：

1. 把当前这一轮收口（能裁决就裁决；实在做不完，`./qr release <ID> "上下文耗尽，未完成，进展见卡片"`，
   **不要留一张半死不活的占坑卡**）。
2. 确认所有结论都已落进假设卡和 `KNOWLEDGE.md`。
3. 在 `rounds/<日期>-<你的名字>.md` 里补一段「跑到哪了」：做了几轮、各自结局、
   下一轮你本来打算做什么、为什么。
4. 汇报一句"上下文将满，状态已全部落台账"，然后就可以换新上下文从启动语重新开始——
   新的你读完 `KNOWLEDGE.md` + `qr leads` + `qr coverage` 就能接上，不需要旧上下文。

## 汇报节奏

- **每轮**：照 `PROMPT.md` 的四段格式写一段（≤20 行）。结论句只能用日常语言，
  指标名和数值放进假设卡 §7。
- **每 5 轮**：加一段自检小结（上面那三个问题的答案）+ 红黄绿总览。
- **停止时**：写清为什么停、停在哪、下一步建议做什么。

判读表和完整数字始终折叠在 `<details>` 里，标成"要复现才看"。
一个没读过这个项目的人，看完你每段的前三行就该知道"能不能用、为什么"。
