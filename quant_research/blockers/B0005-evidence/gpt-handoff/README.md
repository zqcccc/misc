## 1. 已验证的根因

腾讯原始 hfq 与 raw 在普通交易段呈仿射关系 `H=aP+b`，不是仅乘一个因子的收益保真价格。存在非零 b 时，`H_t/H_(t-1)-1` 的分母含有历史加法项，因而与相同股份的价格涨跌不同。这个事实描述的是**数据算法与项目用途不匹配**，不意味着供应商任何用途下都“造假”。

工商银行单次 800 根原始响应内，2023-05-23 至 2023-06-30 用前15天拟合、后12天核验：a=1.04501987、b=3.40464593，后段最大价位残差 0.00039071 元，低于源报价 0.001 元的半个跳动。这无需分页拼接，已排除“只有分页接缝才出错”的解释；没有宣称所有历史分页均无问题，也未把估计 a/b 用于策略收益重建。

五只股票的日收益交叉核验均支持普通日差异；工行 2347 个对齐交易日中，hfq 与 Baostock 报价涨幅差超过1bp有2147天，raw只有12天。数据完整数字见 `audit_results.json`。这证明日常变动被扭曲，**不证明 raw 或 pctChg 在分红送转日可直接代替总收益**。

## 5. 可实施修复方案与完成门槛

1. **建立分用途的数据表**：raw OHLC用于价格/成交；交易所当日参考价、板块、PIT ST和涨跌停价用于交易限制；公司行动事件用于收益与持股数量。停止把一个hfq面板同时作为这三种东西。
2. **保留公司行动原文与日期**：现金金额、送转比例、配股价格及参与、公告/登记/除权/实际到账日。已保存的腾讯响应在分红日第7字段有事件对象；`fetch_history` 的 `b[:6]` 丢掉了它。该字段可作发现入口，不能未经发行人对账就充当完整事件源。
3. **用账户守恒计算结果**：股数×raw价＋可用现金＋应收红利，明确税费与再投资成交。现金分红示例日回报 `(C+D)/P-1`；换成 `C/(P-D)-1` 会隐含另一种再投资，不能混用。到账前红利不增加可交易现金。参考价连乘仅作行情诊断。
4. **先做有明确官方事件的金样本**：普通日、现金分红、差异化分红、送转、配股、跨到账日、停牌与退市；验证信息时间与每项资金恒等式。实测字段缺失则关闭该项验收，不凭拟合补齐、不删掉出错资产。
5. **版本化重建且并存**：保存旧缓存及hash；输出新的数据版本、完整源清单和前缀稳定检查。先核验H0047的四只ETF与511880，再验证小盘完整链路，最后按上述依赖顺序重跑历史卡。只变数据修复，不动已锁的成本、样本期、基准定义或策略参数。
6. **保持阻塞直到证据完成**：B0005不能凭“找到原因”关闭；新数据、成交与现金流对账及重判影响清单完成后再按维护流程处理。B0003还要单独处理H0047的券商追保和换月盘口证据。
