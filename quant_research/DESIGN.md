# 台账设计说明：为什么是现在这个形状

> 写给要改这套东西的人。不看也能用，改之前必须看。

## 它是什么

一本**共享研究台账** + 一个**可版本化的裁判** + N 个异构 agent（claude / gpt / trae /
doubao / workbuddy …）。agent 各自在自己的 worktree 里跑，共用同一份台账。

## 三条地基

### 一、完整性检查看增量，不看绝对状态

**问题**：原来的自检是「`git status --short` 在协议路径下必须为空」。这条规则的本意是
"你不许改协议"，但实现成了"仓库必须干净"，于是**维护者手上有没提交的活儿 = agent 篡改了协议**，
两者不可区分。2026-09-05 一个 agent 因此连续三次开工即停机，零产出。

**做法**：`qr start` 把三组受保护文件（协议目录 / `qr`+PROMPT / templates）的内容指纹
存进 `runs/<agent>.env`；`qr selfcheck` 拿当前状态和**这一趟的基线**比。开工前就存在的
改动落在基线里，不算违规；你改了才算。判据从"仓库是什么状态"变成"你干了什么"。

### 二、裁判可以被修，修裁判的产物是待重判队列，不是全局停机

**问题**：原来的铁律是「协议一个字节都不许变，变了之前所有卡的『按同一套标准判过』就断了」。
但指纹是内容哈希，只能回答"一样还是不一样"，回答不了"这条裁决在新版下还成不成立"。
于是裁判的任何缺陷都变成全局急停事故——**而一套专门用来证伪的系统，它的裁判一定会有缺陷**
（两天里两个 agent 各找到一个真的）。这个设计的稳态是停机。

**做法**：`PROTOCOL_LOG.md` 给每一版协议登记 `版本 / 指纹 / 影响`。`影响` 描述这次改动
**往哪个方向动**：

- `tighten`（门槛变严）→ 只可能翻掉 `PASS`
- `loosen`（门槛变松）→ 只可能翻掉 `FAIL` / `PARK`
- `breaking` → 全部
- `none` → 无

`qr rejudge` 据此算出**待重判队列**：谁需要重跑，谁按当前口径仍然成立。历史卡保留它们
当初盖的指纹，不追溯改写，也不"全部作废"。修裁判从此是一次有限的维护，不是一次事故。

### 三、阻塞是有状态的记录，不是散文

**问题**：原来 agent 停机的理由写在 `rounds/*.md` 里。下一个 agent 读不到状态，只能靠读懂
中文自然语言重新推导"这条还算不算数"——实测烧掉一整个会话、两万多 token，结论是"仍然阻塞"。
而且所有异常同一个严重级：`门禁能被绕过` 和 `维护者有未提交文件` 触发同样的全量停机。

**做法**：`blockers/B****.md`，带 `status`（open/closed）和 `severity`：

| 级别 | 挡不挡开工 | 判据 |
|---|---|---|
| `HALT` | 挡所有 agent | 会让**别人**的研究得出错误结论 |
| `ASK` | 不挡，每次开工提示 | 只让**你自己**这一轮做不下去 |
| `WARN` | 不挡 | 两者都不是 |

一个 agent 卡住不该让整支编队停摆，所以只有 `HALT` 挡路。

## 并发

- **写台账串行化。** `REGISTRY.md` / `KNOWLEDGE.md` 是从假设卡**整体重建**的派生视图，
  两个 agent 同时收口会互相覆盖。所有写命令在 `qr` 入口处拿一把 mkdir 锁，只读命令不加锁。
  锁超过 5 分钟自动回收，一次 Ctrl-C 不会让编队停摆。
- **占坑有归属。** `qr verdict` / `qr release` 要求你是坑主。`qr note` 允许外人写，但会在
  日志里标出"非坑主"——接管前留痕就是这么用的。身份来自 `QR_AGENT`；没有显式身份时
  归属保护自动让路，避免误伤人工操作。
- **接管是 compare-and-swap。** `qr takeover <ID> --expect <原坑主>`：`--expect` 对不上
  说明有人先接了。`qr stale` 的 6 小时只是启发式，没有 `--expect` 两个 agent 会同时接管同一个坑。
- **派生视图永远不要手改。** 手改会在下一次别人裁决时被 `qr index` / `qr knowledge` 覆盖。

## 还没做的

- **重判队列没有闭环。** `qr rejudge` 只列出谁需要重判，没有"已确认不受影响"的登记入口，
  确认过的卡下次还会再列一遍。
- **`qr` 自己不在协议指纹范围内。** 指纹只扫协议目录下的 `.md`/`.py`；`qr` 里那份 PASS
  二次校验被改了，指纹发现不了。它进了 `selfcheck` 的 `cli` 分组，但那只防"本轮改动"，
  防不了跨轮次的漂移。
- **PASS 门禁的校验清单在两处各写一份**（`qbt.py` 的 `validate_gate_statistics` 和 `qr` 的
  内嵌 python），会漂移。
